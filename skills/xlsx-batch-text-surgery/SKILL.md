# xlsx 批量文案手术（Batch Text Surgery）

## 何时用

- 上百至数千个 xlsx 需要把**某几句已确认的旧文案**改成新文案（报告模板演进、口径变更、合规措辞替换）。
- 需要**验证**全库 xlsx 是否还残留某文本。
- **不要用全链重生成**：重生成会夹带处理链上其他未定型的漂移（实测某项目重生一次带出 400+ 处无关变更），
  无法证明「改的恰好是那几句」。手术式补丁只动命中格，diff 可逐格自证。

## 铁律（按顺序全做）

1. **精确句式匹配**：把要改的旧文案写成锚定正则（含完整前后缀、捕获组原样回填），**不要用模糊匹配**。
   只替换这些句式，命中才动。
2. **备份先行且幂等**：每个将被写的文件，先 `shutil.copy2(f, BACKUP_ROOT / f.relative_to(ROOT))`，
   再 `wb.save(f)`。这样中断零损失、重跑安全（已清件再跑命中 0 格）。
3. **只动字符串格**：`isinstance(v, str)` 才处理；数值 / 公式格一律不碰。
   （公式串里若含目标句式，属说明格，可动。）
4. **句式级收尾自校验**：跑完全库用**与补丁同源的句式正则**复扫，残留非 0 则非零退出。
   ⚠️ **不能用词级谓词**——词级会把「不该改的正当文本」误报（实测：准则/程序表里的
   「复核加计正确，与总账数…核对相符」被词级谓词误报，但它是标准程序描述，本来就不该改）。
5. **范围界定**：先把目录分成「本方产物」与「外部/参考件」。用**文件名后缀或结构特征**判定
   （如本方产物统一带 `_AI.xlsx`），外部件不处置，并在报告里如实说明。自证零误伤的办法：
   **备份目录里的文件应当全部是本方产物**。

## xlsx 快扫验证（本方法的关键加速器）

全库逐格用 openpyxl 读太慢（约 4 s/文件，2000 个文件要 1 小时以上）。改用 zipfile 直读 XML：

```python
import html, re, zipfile

def scan(f, rx):
    n = 0
    with zipfile.ZipFile(f) as z:
        for name in z.namelist():
            if not (name.startswith("xl/") and name.endswith(".xml")):
                continue
            txt = z.read(name).decode("utf-8", "ignore")
            # 顺序铁律:先剥标签,再反转义(颠倒会把 &lt; 还原成 < 又被当标签剥掉)
            plain = html.unescape(re.sub(r"<[^>]+>", "", txt))
            n += len(rx.findall(plain))
    return n
```

⚠️ **两个必须知道的坑**：

- **xlsx 内中文以数字实体存储**（「复」写成 `&#22797;`）。少了 `html.unescape` 就是**全库假阴性**
  （实测 1340 个确定命中文件只报 14 个）。
- **openpyxl 保存的 xlsx 通常没有 `xl/sharedStrings.xml`**（字符串以 `inlineStr` 内联在
  `xl/worksheets/*.xml`）。快扫必须同时读 worksheets，只读 sharedStrings 会全漏。

速度收益：**0.016 s/文件 vs 4 s/文件（快 250 倍）**。全库复检 1 小时 → 3 分钟。

**反证纪律**：写完扫描器/谓词，先拿**已知必命中的样本集**（如备份目录的改前原件）验证它能报出来，
再上全库。样本报 0 = 扫描器坏了，不是「已经干净」。

## 执行姿势（大柜时的工程约束）

- **长时后台任务可能被环境静默杀掉**（实测两次 apply 分别死于 1h43m / 52m，无退出码、无汇总行）。
  → 用**前台分批**（每批 ≤200 文件，约 1 分钟）+ **清单驱动补跑**。
- 补跑收敛用**清单精确到文件**：把复检输出的「残留文件清单」直接当输入，
  只处理这些文件。比「按目录/项目重跑」可靠（目录名可能含全角括号导致 `find` 静默报 0）。
- 中途死掉后**不要重跑全柜**：幂等性保证只需补跑残留清单。

## 收尾验收（四项全过才交付）

1. 全库句式级复检 **残留 0**。
2. **抽样单元格级 diff**：备份（改前）vs 现件，逐格比对，断言**非字符串差异 = 0**，
   且差异逐条落在预期句式上（均匀抽样 5-6 件、跨子目录）。
3. 回归测试全绿（若改动涉及代码/夹具）。
4. 记录：改了多少件、备份在哪、跳过了什么（不可读件、外部件清单）。

## 交付话术

明确说清三件事：**改了什么**（句式映射）、**改了多少**（件数/格数）、**没改什么**
（外部件、不可读件及原因）。用抽样 diff 作为「只改了该改的」的证据。
