# 纸质表单 → 单文件 HTML 生成器

## 何时用
用户给出一张**拍歪/模糊的单据照片**，要求复刻版式；或者更进一步要「一个能自己做单据的工具」。默认交付**单文件 HTML（零外部依赖、双击即用）**，而不是静态 Word 模板——后者只能填一次。

## 第 0 步：先问清 4 件事
1. 交付形态：网页生成器 / Word 空白模板 / 两者（默认推荐生成器）
2. 纸张与方向：A4 横向 / A4 纵向 / 按原件尺寸
3. 留空范围：只留空明细、合计与大写自动算 / 全部留空 / 原样照抄
4. 明细行数：保留原件行数 / 固定 N 行 / 自适应

## 第 1 步：读准原件（最容易翻车的一步）
**不要直接把照片丢给 Read 就当读懂了。** 实测：手机拍的旋转文档照片，模型会认错公司名、日期、编号，另一个子 agent 也会编错几处。可靠流程：

1. **摆正**：`Image.open(p).rotate(-90, expand=True)`。方向不要猜——先出 `cw90 / ccw90` 两张缩略图各 Read 一次判断。
2. **分区裁剪 + 放大 2–4 倍**再 Read。整张图会被降采样到看不清；裁到「表头带 / 列头 / 明细区 / 合计区 / 签字栏 / 边缘竖排字」逐块读，小字立刻可辨。
3. **竖排文字**：裁出竖栏后 `rotate(±90)` 转正，必要时 `ImageOps.autocontrast` 增强。
4. **交叉验算**：会计/统计数字用内在逻辑校验（会计凭证用「借贷必须相等」）。**算得平的读数才可信**，算不平的一定有误读。
5. **查表单型号**：纸边常印型号（如「金蝶记账凭证 KP-J107h」）。搜型号即得准确纸张尺寸与标准版式，比目测像素靠谱得多。
6. 拿不准的表头字段**做成可编辑输入框**，预填最佳读数并在交付时说明——不要因为一个字看不清就卡住。

参考脚本骨架：
```python
from PIL import Image, ImageOps
im = Image.open(SRC).rotate(-90, expand=True)      # 摆正
c = im.crop((l, t, r, b)); c = c.resize((c.width*k, c.height*k), Image.LANCZOS)
c.save(out)                                        # 再 Read 这张
```

## 第 2 步：搭版式（单文件 HTML）
- 纸张：`.sheet{width:297mm;min-height:210mm;padding:13mm 12mm 13mm 14mm}`，**所有尺寸用 mm**。
- 打印：`@page{size:A4 landscape;margin:0}`；`@media print` 里隐藏工具条、`transform:none`、去阴影。
- 表格：`border-collapse:collapse; table-layout:fixed` + `<colgroup>` 定列宽。
- 表头带用 `display:flex` 分左右；签字栏另起一张表（或见下方列数陷阱）。
- 颜色：单据表格线一般是浅蓝灰（`#8fb3cb`），表头/合计行浅蓝底（`#dbe8f2`），表头文字蓝（`#2f6fa6`）；中文 SimSun，数字 Arial。
- 屏幕自适应：包裹层 `transform:scale(k)`（k = 可用宽 / 纸张像素宽），打印时复位。297mm ≈ 1122px，普通屏幕不缩放也放得下。

## 第 3 步：录入与计算
- 状态对象 `{header:{...}, sign:{...}, rows:[...]}`，**每次输入只更新数据 + 重算，不要重渲染单元格**（否则光标丢失）。
- 摘要/科目这类长文本用 `contenteditable` div（能自动撑高换行），金额用 `<input>` 右对齐。
- 键盘：`Tab` 下一格、`Enter` 下一行同列（避免用 `idx+2`，先确认每行可编辑元素个数，本次是 4 → `idx+4`）、`Shift+Enter` 格内换行。
- 金额：输入即存原值，`blur` 时格式化为千分位+两位小数，`focus` 时还原成裸数字。
- 合计、人民币大写、借贷平衡提示实时算。
- 人民币大写要点：跨节补零规则 =「本节数值 < 1000 且前面已有内容且不以零结尾时补零」；`0.05` 输出「伍分」而不是「零伍分」。**用 node 跑用例表验证**（含 50004 / 1000001 / 10000002 这类边界）。

## 第 4 步：输出与留存
- 打印/导出 PDF：直接 `window.print()`。
- 导出 Word：行内样式 HTML + `Blob(["\ufeff"+html],{type:"application/msword"})` → `.doc`，Word/WPS 可直接编辑。纸张用 `@page WordSection1{size:297.0mm 210.0mm;mso-page-orientation:landscape;margin:...}`。
- 备份：localStorage 自动保存 + 导出/导入 JSON。
- 加一个 `#demo` 地址参数载入示例数据、暴露 `window.xxxApp` 调试句柄——自检和后续自动化都靠它。

## 第 5 步：自检（无 playwright 也能做）
Chrome 路径按本机安装位置确定（示例：`C:/Program Files/Google/Chrome/Application/chrome.exe`，或 Playwright 自带的 `.../ms-playwright/chromium-*/chrome-win64/chrome.exe`）
```bash
# 高清截图，再裁剪局部看细节
chrome --headless=new --disable-gpu --no-sandbox --hide-scrollbars \
  --force-device-scale-factor=2 --window-size=1180,760 --virtual-time-budget=4000 \
  --screenshot=out.png "file:///D:/path/x.html#demo"
# 打印分页/纸张验证
chrome --headless=new --disable-gpu --no-sandbox --no-pdf-header-footer \
  --print-to-pdf=out.pdf "file:///D:/path/x.html#demo"
```
PDF 用正则数 `/Type /Page`，读 `/MediaBox` 换算 mm，确认「页数正确 + 每页 297×210mm」。
交互验证：复制一份 HTML，注入脚本把结果写进 `<pre id="__t">`，再 `--dump-dom` 抓出来。
> ⚠️ **注入必须用 `rfind('</body>')`**。`replace('</body>', ...)` 只会命中第一个，而这类工具里「构造导出 HTML 的 JS 字符串」中也含 `</body>`，注入会嵌进字符串导致静默失效。
> ⚠️ **`confirm()` 在 headless 里会真的阻塞、不自动关闭**（实测挂死 4 分钟），必须先在脚本最前面替换成桩：
> `window.__confirms=[];window.__confirmAnswer=false;window.confirm=function(m){window.__confirms.push(m);return window.__confirmAnswer;};`，要测「点确定」分支再把 `__confirmAnswer` 置 true。
> ⚠️ 截图窗口高度要够（整页 ≥ 纸张高度 + 工具条），否则页面下半截拍不到。

**验「打印态」CSS 的土办法**：把 `@media print{...}` 临时替换成 `@media all{...}` 再截图，直接看到打印时哪些声明真的生效——用它确认「待填虚线不上纸」「聚焦底色不上纸」这类承诺。

**node 测纯函数**：正则截出 `function parseAmt` 到渲染段之间的代码 `eval` 后跑用例表（含边界值），比在浏览器里测快得多。

## 坑位清单
- **表格列数必须自洽**：主表 5 列 + 签字栏 6 格 → 一张表会多出第 6 列并搞乱列宽。解法：用 30 个基础列（如 8/10/5/5/2）做 `<colgroup>`，主表用 colspan 拼、签字栏 6×colspan5，全表恒定 30 列。
- 带 `rowspan` 的单元格已覆盖的行，**不要再给它加同位置的 `<td>`**，否则浏览器会静默丢弃并留下死 CSS。
- 同一条消息里对同一文件发多个 Edit 会互相覆盖，必须逐轮顺序编辑。
- 纸边厂商印字（如「金蝶记账凭证 KP-J107h」）不是单据内容，做成开关项、默认状态交付时说明。
- 分页单据（页号 x/N）每页借贷天然不平，平衡提示要说明这一点，避免用户以为算错。

### 改造既有生成器时最容易踩的四个坑（2026-09-11 实测）
1. **静态渲染 vs 实时更新**：把某块 UI 从「recalc() 直接改 DOM」改成「rebuild() 一次性渲染」后，**必须同时让 recalc() 去刷新它**，否则该块永不更新。本次就因此让「合计/大写」在录入时不再变化，靠自检才发现。
2. **localStorage 必须全走 `safeGet/safeSet`**：直接访问（含 `getItem`）在存储被禁时会抛 `SecurityError`；若它在启动流程中间，后面所有脚本都不执行、页面空白。别只包 `setItem`。
3. **调试后门要隔离**：`#demo` 之类入口若与正常模式共用同一个存储键，用户一编辑就把真实数据覆盖了。做法：demo 下 `save()` 直接 return + 独立键 + 顶部提示条。
4. **会删数据的操作必须确认**：改「行数」或点「减行」会删掉末尾行及其内容，静默删除即数据丢失；仅当被删行确有内容时才 `confirm()`，「减行」优先删末尾第一个全空行。

### 多页分页设计（原件是多联/多页表单时）
- 每页行数固定（与原件一致，如 9 行），数据模型不变，渲染时按行数切片成多个纸张元素；每页重复表头带/列头/合计/签字栏（原件每页也是完整表单）。
- 打印：`.sheet{break-after:page}` + `.sheet:last-child{break-after:auto}`，配合 `@page{size:A4 landscape;margin:0}`，实测 20 行 → 恰好 3 页、每页 297×210mm。
- **合计口径选「整张单据合计」**：多页单据的原件通常在每页都印同一个总计（本次原件的页 1/3 就印着全凭证 507,975.28，而本页只有 362,037.64）。按整张合计 → 各页合计一致、平衡判断也按整张来，分页不再误报不平。
- 页号给一个「自动 1/N」开关；演示/示例数据时自动关掉并还原原件上的 `1/3`，以忠实复刻。
- 表头字段若做成可编辑：**只在第 1 页渲染输入框，其余页渲染静态文本**，用 `data-xxx` 属性统一同步，避免同一字段出现 N 个输入框互相打架。

### 复刻版式要"逐条数线"，别只看外框（血泪教训）
交付后被用户圈出「这里应该也有线条」——**合计行与签字栏之间的横向分隔线没了**。
根因：CSS 里写了 `.grid tr:last-child td{border-bottom:none}`（本意是避免和外框重复），把末行的下边框去掉了；而紧跟其后的签字栏表格只有左边框、没有上边框 → 那条分隔线整条消失。原图该处**是有线的，且贯穿整宽**。
修法：删掉该规则，并加注释锁住这个意图；改完**必须检查加 1px 边框会不会把页面撑高**（本次实测每页仍为 794px = 210mm，没多出页）。
**正确做法**：把原图的横线/竖线位置**逐条列出清单**，与渲染结果做集合比对——缺哪条一目了然。本次就是靠「192dpi 渲染 PDF → 逐行统计暗像素 → 得横线 y 清单（13 条 vs 应为 14 条）」定位并验证的。
> 交付 PDF 时若 Windows 下报 `Permission denied` 覆盖失败：用户正开着该文件（或被内置预览占用）。另存一个新名字并明确告知，别反复重试。

### 打印/导出必须与屏幕一致：别用 CSS background 画底色（血泪教训）
**Chrome 打印对话框的「背景图形」默认不勾选 → 所有 CSS `background`（含 `background-image`）都不打印**；Word 默认也不打印背景色。于是屏幕上好看的浅蓝表头带、列头行、合计行，用户另存 PDF 后**全部变白**，直接投诉"跟 HTML 不一致"。
**为什么自查看不出来**：无头 `--print-to-pdf` **默认带背景**，本地永远正常，只有用户手动打印才暴露。
**做法**：关键色带改用**内联 SVG `<rect>`**（SVG 是图形内容，不受该开关影响），并**删掉对应的 CSS background**，让屏幕和打印用同一来源。坐标先用 `getBoundingClientRect` 实测、换算成 mm 写死；覆盖层 `position:absolute;width:297mm;height:210mm;z-index:0`，被覆盖的容器 `.frame` 设 `position:relative;z-index:1`。Word 版给带底色的 `<td>` 补 `bgcolor` 属性（Word 认表格底纹比认 CSS background 可靠）。
**验证必须用 `printBackground:false`**（CDP `Page.printToPDF`），否则等于没验。
**沙箱坑**：CDP 的 WebSocket 走不通——**沙箱拦截本机 TCP**（curl 127.0.0.1 → 000 / exit 7）。改用 Chrome 的 **`--remote-debugging-pipe`**：`spawn(chrome,['--headless=new','--remote-debugging-pipe',url],{stdio:['ignore','ignore','ignore','pipe','pipe']})`，消息以 `\0` 分隔；先 `Target.getTargets`，再 `Target.attachToTarget{flatten:true}` 取 sessionId，然后 `Page.printToPDF`。`--user-data-dir` 不能用 Git-Bash 的 `/tmp/...`（Chrome 不认），要用 Windows 风格路径。
**判定"确实只是渲染差异"**：比对表格横线 y 坐标逐条差值 + 内容外框四点，全为 0.00mm 才敢说"布局一致，剩下只是反锯齿"。

### 交付后改内置默认值常常"不生效"（必看）
给已交付的单文件工具改内置默认值（`DEFAULT`/`SEED`）时，只要用户**用浏览器打开过一次**，`localStorage` 就已存了旧状态，启动时 `load()` 的返回值会盖掉新默认值。
- 正确解法：**在 `load()` 里做字段级合并** —— 本地存的字段若为空、而默认值有内容，就用默认值补上。既让新默认生效，又不丢用户已输入的内容。
- 别图省事换 `LS_KEY`：那会连用户改过的东西一起丢，只在"交付全新文件、用户从未打开"时才安全。
- 改完立刻回读确认结构：Edit 的 `old_string` 若多带了行而 `new_string` 没带上，会**静默删掉代码**（本次就把 `rows:[] };` 删了，导致整页 JS 语法错误）。新旧字符串覆盖的行数必须一致。
- 判断"某变量是否已就绪"要比较**调用点**位置，不是定义位置（`var` 提升 + 赋值顺序）；比错了会得出假警报。

### 底稿明细 → 会计凭证时的科目口径（重要）
审计/会计底稿里的科目名**不是会计科目**（"应收账款原值""存货原值""固定资产原值""年初未分配利润—上年审定数""无形资产—累计折耗""国有资本"……）。做凭证前必须先映射到带编码的准则科目（1122 应收账款、1405 库存商品、1601 固定资产、1602 累计折旧、1701 无形资产、1702 累计摊销、2202 应付账款、2205 预收账款、2241 其他应付款、4001 实收资本、4002 资本公积、4104 利润分配—未分配利润、6901 以前年度损益调整…），**并保留底稿的二级信息**（往来单位、年度、明细）作为二级科目，既规范又可追溯。拿不准的（如"国有资本"）要单独标出来请用户确认，不要猜。
跨年度调整先走 6901 以前年度损益调整，期末结转至 4104（会多出结转分录）；若 6901 里混有非损益类（重分类、冲回期初数），要提醒用户。
**校验**：逐笔展开后按"编码+科目名"**前缀**汇总（按全名匹配会漏掉带二级的科目），与手头已有的汇总凭证逐项比对——注意汇总凭证把负债/权益/收入记在贷方栏带符号，与"借−贷"净额符号相反，别误判为差异。

### 像素测量的能力边界（重要）
暗、糊、卷边、倾斜的手机照片**不足以精确反算列宽**：本次竖线检测给出的序列互相矛盾、目视标尺估计误差达 ±30%。能稳拿的只有「行距」这种高重复周期量（实测 ≈54px；用纸张宽度 1218px↔297mm 折算 ≈13.2mm/行）。
→ 其余尺寸不要硬改，**如实说明并索要清晰正面照**，比用不可靠数据改坏可靠版式更专业；同时把「测不出」这件事写进交付说明。
